# 产品边界

本文描述当前可从产品界面进入并由活动代码执行的能力。规划、讨论稿和文件存在本身不能作为功能可用的证据。

## 产品定位

ResearchPath（研径）是 Windows 本地优先、点按式、按需执行的实证研究工作台。React 提供交互，FastAPI 管理数据、AnalysisIndex、任务、契约与本地持久化，R 执行统计估计。目标用户是需要可复现分析与结构化导出的个人研究者，不是云端协作平台或自动“找显著”系统。

已有数据的主界面固定为三个一级工作区：

1. **数据**：导入后直接查看数据，并按需进入变量、量表、质量、结构、合并和派生工具；
2. **分析**：从唯一方法库选择方法，方法自身根据当前上下文决定可用性；
3. **输出**：查看 AnalysisDocument、不可变运行、主要结果、非当前设置结果和模型/高级分析的服务端运行引用。

研究规划和功效可在没有活动数据时单独使用。时间结构、依赖结构和研究设计仍由 `StudyContextSwitcher` 声明，但它们是方法适用性的上下文，不是额外一级工作区。

测量版本按方法需要创建，不是所有统计分析的全局门槛：原始变量的描述、频数、缺失、相关、组间比较、回归、相对重要性与响应面可以没有测量版本；构念计分、量表方法及当前 PROCESS/SEM、面板和日记专用流程仍按各自能力要求绑定测量版本或结构版本。

## 当前正式接线

| 领域 | 活动入口 | 当前边界 |
| --- | --- | --- |
| 数据 | `DataWorkspace`、datasets routes | CSV/XLSX/SAV/DTA/POR、只读数据视图、变量类型、数据质量、结构、合并、测量版本 |
| 方法库 | `ContextCapabilityCatalog`、`methodRegistry.json` | 全部产品可见方法统一检索；方法局部守门，不使用一个全局 `analysisReady` 代替方法前提 |
| 基础实证 | `EmpiricalAnalysis`、`run_empirical_analysis.R` | 描述、频数、缺失、相关、测量、比较、聚合、回归、响应面、纵向与日记专用路径 |
| PROCESS/SEM | `ModelBuilder`、model job/result、`run_analysis.R` | 常见 PROCESS 表单、完整 55 编号目录、基础 SEM 表单和高级画布共用现有 ModelSpec/冻结/运行链 |
| 高级分析 | `AnalysisWizard`、advanced job/result、`run_advanced_analysis.R` | ICC/rwg、两层 Gaussian LMM、实验、功效、MI、高级测量，以及已登记的面板/日记专用能力 |
| 输出 | `OutputWorkspace`、`AnalysisIndexService` | 服务端保存 AnalysisDocument/AnalysisRun 身份与上游版本；统计结果仍由对应 job/report/result 服务权威保存 |

方法注册表的 `executionAvailable=true` 只表示当前 runner 可以执行；它不表示已完成独立数值验证，更不表示可直接作为论文主分析。每个活动切片同时返回 validation/maturity/publication 元数据。界面调整不会提高统计成熟度或发表资格。

## Data / Analyze / Output 工作流

### Data

导入成功后直接显示数据。Data View、Variable View 与 Scale/Measurement 是稳定子视图；质量、结构、合并和派生能力按需打开。可靠的 inferred type 可用于不要求确认类型的方法；只有具体方法需要时才要求局部确认，不再用“确认全部变量”作为所有分析的统一阻塞条件。

### Analyze

用户只在统一方法库选择一次方法。方法卡展示当前可运行、需要设置或不适用的状态；进入方法后直接配置变量、角色和参数，不出现第二个全局方法选择器。打开配置不会自动估计，运行始终是显式操作。

常见 PROCESS 直接表单化：

- Model 4 简单中介：X/M/Y；
- Model 4 并行中介：X/M1/M2/Y；
- Model 6 链式中介：X/M1/M2/Y；
- Model 1 简单调节：X/W/Y；
- Model 7 第一阶段调节中介：X/M/W/Y；
- Model 14 第二阶段调节中介：X/M/W/Y。

上述表单只构造现有 ModelSpec。Model 14 中 W 调节 M→Y，因此均值中心化使用 M/W；Model 1 与 Model 7 分别调节 X→Y、X→M，使用 X/W。完整 PROCESS 目录和高级 SEM Studio 继续用于复杂或自定义模型。

高级方法不被强行改造成同一张表单：ICC/rwg、LMM、实验、解析功效、Monte Carlo、MI 和高级测量保留各自已验证的专用配置器，但共享统一方法库、标题/运行检查和 Output 归宿。

### Output

Output 的服务端 `AnalysisIndex` 只保存：

- AnalysisDocument 身份、标题、方法、数据/测量版本、置顶和主要结果；
- AnalysisRun 的 runId、所属 AnalysisDocument、方法身份、来源与上游版本；
- 从既有 model/empirical/advanced job state 可重建的运行引用。

它**不复制统计结果**。权威结果仍在现有服务：empirical report、model result、advanced result。浏览器 localStorage 只保留即时草稿和 UI 状态；删除浏览器缓存不会删除服务端任务或报告，也不会使项目运行索引永久消失。

非当前数据/测量版本上的结果继续可见并标记“基于非当前设置”。修改当前分析设置不会覆盖已提交运行。复制 AnalysisDocument 创建新的草稿/分析身份，不继承原 run/result identity。

## 研究上下文与结构边界

研究上下文分别声明：

| 维度 | 当前选项 | 作用 |
| --- | --- | --- |
| 时间结构 | 单次/横截面、追踪面板、密集追踪 | 决定波次、时间和滞后准备 |
| 依赖结构 | 独立、聚类/嵌套 | 决定 cluster、ICC、聚合和多层模型门槛 |
| 研究设计 | 观察性、随机实验、非随机比较 | 决定处理/对比入口和解释边界 |

非随机比较使用内部 `quasi_experimental` 枚举值描述研究设计，但当前不对外声明 DiD、IV、RDD、IPW、合成控制等准实验因果识别能力。嵌套数据不会因为 UI 选择而绕过依赖结构门槛。

## PROCESS 5.0 识别与执行边界

目录版本为 `5.0`，覆盖编号 1–22、28–29、58–73、75–76、80–92，共 55 个当前预编程模型；Model 74 不在当前目录。55 个有效预设在满足各自中介数量约束时可搜索、预览、应用并进入现有执行链；合法但未命中编号的自定义拓扑可保存、冻结和导出设计，但任务服务拒绝运行。

PROCESS 编号执行仅接受连续或 0/1 二分类的 X；W/Z 与协变量同样要求连续或二分类。M 只接受连续变量；二分类中介在运行前返回 `BINARY_MEDIATOR_NOT_SUPPORTED`。多类别 X（官方宏 `mcx` 功能）当前不执行，不会静默转成哑变量后冒充支持。

编号估计器是基于公开模型拓扑的独立实现，不在仓库中复制或分发官方 PROCESS 宏。数值验证、golden/oracle 与各方法的估计边界以 [统计方法与报告规范](02-统计方法与报告规范.md) 和 [能力矩阵](07-能力矩阵与路线图.md) 为准。

## 视觉、响应式与可访问性现状

日常 Data / Analyze / Output 工作台使用稳定不透明表面、轻边框、紧凑标题和较小圆角，不再依赖全局 glass stylesheet。专家 PROCESS/SEM 编辑器的视觉层独立在 `expert-model.css`，不会向普通工作台泄漏 blur/floating-card 效果。

工作台具备：

- Data/Analyze/Output tab 的方向键、Home/End 导航；
- 跳到活动工作区的 skip link；
- `:focus-visible` 焦点；
- `prefers-reduced-motion`；
- `prefers-contrast` 与 forced-colors 回退；
- 1366/1024/760/420px 响应式收敛；
- Playwright axe 与横向溢出自动检查。

自动化可用性检查不等于真实用户研究。真实受试者任务完成率、误操作率和主观负担只能在有人参与的可用性测试后形成外部证据，仓库不能自动生成这类结论。

## 暂停与不支持

- 云端账户、遥测、远程数据同步或多人实时协作；
- 未在活动注册表登记的任意高级方法组合；
- 准实验因果识别：fixed effects、DiD/event study、IV/2SLS、RDD、IPW/overlap、synthetic control；
- 三层或任意交叉分类结构、通用广义多层中介、连续时间模型、潜变量/高阶动态 SEM；
- 无人值守地把可执行性自动升级为“论文级主分析”。

## 权威顺序

发生冲突时依次检查：

1. 活动代码、服务端路由和测试；
2. `project.manifest.json` 与机器可读 capability evidence；
3. 本目录的产品与工程文档。
