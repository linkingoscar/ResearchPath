# UX / IA 产品规范

## 产品心智模型

ResearchPath 面向个人研究者，采用 Data / Analyze / Output 三工作区。一级导航回答三个问题：数据是什么、要做什么分析、结果在哪里。研究设计、时间结构、依赖结构和测量版本是方法适用性的上下文，不建立平行流程。

## Data

- 导入完成后直接显示数据，不以向导阻塞查看。
- Data View、Variable View、Scale / Measurement 是稳定子视图；质量、结构、合并和派生工具按需展开。
- 原始数据只读；清空当前界面上下文不删除数据文件、草稿、任务或结果。
- 方法只在确有需要时要求变量类型、测量或结构确认，不设置全局“全部确认后才能分析”的门槛。

## Analyze

- 所有可见方法从唯一方法库检索和进入。
- 方法卡明确显示可运行、需要设置或不适用，并给出具体原因。
- 选择方法后直接进入该方法的变量、角色和参数配置，不再要求二次选择同一方法。
- 打开配置不会自动估计；运行必须由用户显式提交。
- 常见 PROCESS 结构提供直接表单，高级 PROCESS / SEM、纵向、日记、多层、实验、功效、插补和高级测量保留各自必要的专用配置。
- 同一方法可以创建多个独立 AnalysisDocument；复制分析不会覆盖原草稿或结果。

## Output

- 以 AnalysisDocument 组织运行，区分主要结果、最新运行、其他版本和失败状态。
- 每次运行不可变；修改设置后重新运行会产生新的 AnalysisRun。
- AnalysisIndex 只保存导航和身份引用，不复制或改写统计结果。
- 结果必须能追溯数据、测量、方法、规格、随机种子、实际执行路径、警告和诊断。
- 批量导出只调用各结果类型的权威导出接口。

## 渐进披露

- 日常界面优先呈现任务、状态、主要操作和主要结果。
- 实现细节、内部 ID、版本哈希和完整诊断放入技术详情。
- 警告、不可发布原因和统计回退不得隐藏在折叠区内。
- 实验性能力必须同时展示支持边界和成熟度，不能仅凭运行成功宣称论文级可用。

## 响应式与可访问性

- 1366、1024、760 和 420 像素宽度下不得出现页面级横向溢出。
- 各工作区的主要操作在窄屏仍须可见、可聚焦、可键盘到达。
- 一级 tab 支持方向键、Home / End；页面提供 skip link 和清晰的 `:focus-visible`。
- 支持 `prefers-reduced-motion`、`prefers-contrast`、forced colors 和无 `backdrop-filter` 环境。
- 普通工作台使用稳定不透明表面；专家画布的视觉层不得影响日常界面。
- 自动化覆盖严重无障碍问题、焦点可达性和横向溢出；真人任务表现按单独的可用性方案验证。

## 验收标准

1. 用户导入数据后无需经过无关步骤即可查看数据。
2. 任一产品可见方法只有一个发现入口，并准确说明当前适用性。
3. 配置、运行和结果三种状态不会混为一体。
4. 修改分析不会静默覆盖既有运行。
5. 数据、方法、模型和结果的主要操作在规定断点及键盘路径中可达。
6. 自动化验证与真人可用性结论分开记录，前者不能替代后者。
