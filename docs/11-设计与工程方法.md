# 设计与工程方法

## 单一事实来源

- 能力是否可执行由服务端 registry 与具体 spec 校验决定，界面和文档不维护平行名单。
- 统计结果只在 engine / service 产生，前端只做格式化和呈现。
- AnalysisIndex 保存对象身份和运行引用，不复制结果真值。
- 同一跨语言概念由源 schema 驱动 Python、TypeScript、OpenAPI 和测试同步变化。

## 显式失败优于静默降级

- 请求方法、实际执行方法、回退原因和适用性边界分别记录。
- 非有限值、退化样本、奇异拟合、无效 bootstrap、未收敛和不完整校正族必须产生结构化状态或警告。
- 局部统计失败不应无解释地拖垮无关结果；无法解释的结果也不能伪装为成功。
- 任务完成、统计估计成功、推断有效和论文可用是不同状态。

## 版本与身份先于路径

- 数据、测量、研究计划、分析文档、运行和结果使用稳定身份并显式绑定版本。
- 任何文件或数据库副作用都同时校验 containment、对象所有权、来源身份和资源预算。
- 修改配置产生新运行，不覆盖既有结果；恢复和导出必须使用运行自身绑定的上游版本。
- 临时路径、缓存键和进程号不能单独作为对象身份。

## 统计实现规则

- 先写方法边界、输入编码、估计器、诊断和报告契约，再接 UI。
- 用户请求与执行器实际采用的估计过程必须可比较；前端不得重新计算置信区间、显著性或效应值。
- 多重性、置信水平、缺失数据策略、样本流和调整变量角色在分析前声明，在结果中可追溯。
- 每个统计切片至少覆盖正常值、退化边界、错误映射、结果契约和代表性数值对照。
- 可运行不等于已独立验证；能力成熟度和论文资格只从明确证据派生。

## 异步任务与资源所有权

- 提交、取消、完成和持久化之间的竞态必须在写结果前复查终态。
- 进度通道断开不改变任务事实；前端使用有界重连或轮询恢复。
- 取消只终止当前任务拥有的进程树，不按进程名或未校验 PID 清理。
- stdout / stderr、监听器、worker、临时目录和并发任务都有明确容量上限与释放路径。

## 界面与研究表达

- 用户只在一个方法库选择方法；局部守门说明缺少什么，不用全局步骤强迫所有研究走同一路径。
- 重要警告和不可发布原因出现在主要结果区，技术细节渐进披露。
- 观察性分析使用关联性语言，不把显著性写成理论支持，也不把中介结果自动写成因果机制。
- 可访问性、键盘路径、窄屏和高对比度属于功能要求，不是发布后的视觉修饰。

## 轻量验证策略

- 日常改动运行 Quick，并补充与改动最近的一组测试。
- 统计公式、跨语言契约、安全边界或任务生命周期变化运行对应专项。
- Full 只用于跨领域高风险变更和发布候选。
- 一个风险只设置一个权威检查，避免在多个脚本、文档哈希和工作流中重复证明同一事实。
- 临时日志和截图用于定位，不进入长期文档；发布记录只保留候选提交、环境和关键步骤结果。
