# 产品工作流与交互

日常已有数据分析以 Data / Analyze / Output 三个工作区为主。

## 1. 首屏与两条主路径

首屏只区分两件事：

- **导入数据并开始分析**：进入 Data / Analyze / Output 工作台；
- **功效与研究规划**：没有数据也可单独使用，不阻塞已有数据分析。

研究上下文仍声明时间结构、依赖结构和研究设计，但它服务于方法适用性，不成为第四个导航层。

## 2. Data：导入后先看数据

Data 的默认目标是“看见当前数据”，不是完成一条长准备流水线。

### 稳定子视图

1. **Data View**：只读预览当前数据版本；
2. **Variable View**：查看名称、标签、inferred/confirmed type、缺失和取值；
3. **Scale / Measurement**：管理构念、题项、反向题、计分和测量版本。

质量检查、研究结构、合并、筛选和派生工具按需打开。可靠 inferred type 可继续供普通方法使用；只有具体方法明确需要 confirmed type 时才局部门禁。量表也只在依赖构念/题项定义的方法上成为前提。

数据、字典、测量和结构版本变化不会删除已提交结果，但相关草稿/运行会被识别为非当前上下文。

## 3. Analyze：方法只选一次

Analyze 只有一个方法库。用户可按关键词、研究任务、当前状态和方法层级筛选；方法卡显示：

- 可直接配置；
- 需要补充设置；
- 当前数据不适用；
- 实验性/成熟度边界。

选择方法后直接进入该方法的变量、角色与参数配置。表单内不再出现另一个全局方法菜单。打开配置不会运行分析；只有显式“运行”才提交任务。

### 3.1 基础实证

描述、频数、缺失、相关、信度、EFA、CFA、效度、共同方法诊断、等值性、组间比较、ICC/rwg、回归、相对重要性、响应面等，从统一方法库直达现有配置器。每次只运行选中的方法及其必要统计依赖，不自动生成“全套论文包”。

### 3.2 常见 PROCESS 表单

常用模型直接表单化，并继续写入现有 ModelSpec：

| 方法 | 模板 | 角色 |
| --- | --- | --- |
| 简单中介 | Model 4 | X / M / Y |
| 并行中介 | Model 4 多中介 | X / M1 / M2 / Y |
| 链式中介 | Model 6 | X / M1 / M2 / Y |
| 简单调节 | Model 1 | X / W / Y |
| 第一阶段调节中介 | Model 7 | X / M / W / Y |
| 第二阶段调节中介 | Model 14 | X / M / W / Y |

所有表单统一提供置信水平和 Bootstrap 次数；包含调节时提供中心化设置。Model 1/7 的被调节预测项为 X，因此中心化 X/W；Model 14 调节 M→Y，因此中心化 M/W。

应用表单只更新当前可撤销草稿，不自动运行。应用后同页显示既有校验、冻结和运行控制。需要自定义路径、更多编号或复杂测量时进入“高级编辑器”；完整 55 PROCESS 编号继续可达。

### 3.3 基础 SEM 与高级 SEM

基础 SEM 提供两构念 X→Y 表单，使用当前 MeasurementVersion，选择已支持 estimator、置信水平和 missing 策略。复杂测量、多组、高阶、约束模型进入 SEM Studio；表单与画布共用相同 ModelSpec 和运行结果身份。

### 3.4 高级方法

高级方法共享统一方法库、标题/运行检查和 Output，但保留最适合自身的配置器：

- ICC/rwg 与两层 Gaussian LMM；
- 面板 CLPM / RI-CLPM / LCM-SR 等；
- 日记/ESM LMM、GLMM、多层中介、DSEM；
- Factorial ANOVA、ANCOVA、重复测量、混合设计、cluster-robust GLM；
- 解析功效和 Monte Carlo；
- MICE + Rubin 合并；
- 高级 reliability/EFA/CFA/invariance、ESEM/Bifactor/IRT/DIF、Marker/ULMC。

“统一”指稳定的发现、标题、检查、运行和输出外壳，不意味着把所有高级方法强行塞进同一张表单，也不重写 R runner。

## 4. Output：AnalysisDocument 与不可变运行

Output 以项目为范围，不只显示当前页面最近一次结果。

### AnalysisDocument

每个分析对象至少保存：

- title / methodId / category；
- source（empirical / model / advanced）；
- datasetVersionId / measurementVersionId；
- 当前草稿身份；
- latestRunId / primaryRunId；
- pinned / archived；
- 创建与更新时间。

同一方法可以创建多个独立 AnalysisDocument。复制分析会创建新的 AnalysisDocument 和草稿作用域，不继承历史 run/result identity。

### AnalysisRun

每次显式提交产生不可变运行引用。修改设置只改变后续草稿，不覆盖已提交运行。用户可：

- 查看运行历史；
- 指定/取消主要结果；
- 打开某个历史运行的只读结果；
- 对非当前设置的结果使用当前数据新建配置。

### 服务端恢复

服务端 `AnalysisIndex` 保存 AnalysisDocument/AnalysisRun 的导航身份和上游版本，不复制统计结果。真正的结果仍分别位于 empirical report、model result、advanced result 服务。

浏览器 localStorage 保存即时草稿和界面状态，不是运行索引的权威来源：

- 浏览器缓存存在时，Output 合并本地草稿元数据和服务端索引；
- 浏览器缓存为空时，服务端索引仍恢复文档/运行；
- AnalysisIndex 文件缺失时，可从经过身份/路径验证的持久化 job state 重建运行引用；
- 非当前数据/量表版本的结果继续显示“基于非当前设置”。

## 5. 研究上下文的三个正交维度

| 维度 | 当前选项 | 作用 |
| --- | --- | --- |
| 时间结构 | 单次/横截面、追踪面板、密集追踪 | 决定波次、时间和滞后准备 |
| 依赖结构 | 独立、聚类/嵌套 | 决定 cluster、ICC、聚合和多层模型前提 |
| 研究设计 | 观察性、随机实验、非随机比较 | 决定处理变量、对比和解释边界 |

例如班级内学生只测一次是“横截面 + 嵌套”，重复测量随机实验是“面板 + 随机实验”。非随机比较不会解锁未实现的准实验因果识别方法。

## 6. 草稿、运行与上游变更

- empirical 草稿按 AnalysisDocument + 数据/字典/测量/上下文作用域保存；
- model 草稿由服务端恢复，编辑后需重新校验/冻结；
- advanced 分析从当前 analysis draft 启动；
- 已提交任务恢复只重连，不自动重跑；
- 上游版本变化使非当前草稿/结果进入 stale，而不是删除；
- storage 写入失败必须显式提示，不能假装已保存。

## 7. 缺失与多重插补

数据阶段只做缺失率、模式、结构性缺失和完整案例损失诊断。正式 MI 在分析前声明 substantive model，保存 ImputationPlanVersion 后再运行 MICE。当前通用路径围绕冻结的线性回归消费者进行 Rubin 合并；改变 substantive model 需要重新验证/插补。MI 运行完成后同样进入 Output 的服务端运行索引。

## 8. 可访问性与响应式

### 键盘

- Data/Analyze/Output 使用 APG tab 模式；方向键、Home/End 自动激活；
- 首个可聚焦 skip link 可跳过 Header/导航，直接聚焦当前 tabpanel；
- `Ctrl+K` 打开命令搜索；
- 所有主要表单、按钮、链接和自定义 tabpanel 提供 `:focus-visible`。

### 视觉偏好

- routine workbench 不使用 backdrop blur；
- `prefers-reduced-motion` 关闭工作台动画/过渡；
- `prefers-contrast: more` 提高边框分辨；
- Windows forced-colors 保留边界和选中状态；
- 专家 PROCESS/SEM 样式独立在 `expert-model.css`。

### 响应式

1366px 以下压缩外边距和卡片网格；1024px 调整 Header/摘要/构念表单；760px 进入单列操作和 sticky 三工作区导航；390px/420px 保证主要操作不产生页面级横向溢出。宽统计表仍通过具名、可聚焦的局部滚动区域访问。

## 9. 可用性验证边界

自动化可以验证：

- 关键任务入口可达；
- 键盘 tab/skip 路径；
- axe critical/serious 违规；
- 390px 横向溢出；
- routine Header/导航没有全局 backdrop-filter。

自动化不能替代真实用户研究。任务完成率、完成时间、错误率、SUS/主观负荷等必须由真实参与者产生；如果尚无外部受试者证据，文档只能标记为“待人工用户测试”，不得伪造通过结论。

## 10. 统计解释边界

界面只把置信区间、调整后 p 值等描述为统计推断信号，不把单条显著路径包装成理论支持，不把观察性/横截面模型写成因果。方法、估计器、警告、多重比较、缺失和发表资格的权威规则见 [02-统计方法与报告规范.md](02-统计方法与报告规范.md)。
