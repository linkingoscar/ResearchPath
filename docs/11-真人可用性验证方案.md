# 真人可用性验证方案

> 状态：待外部参与者执行  
> 目的：验证两份 UX / IA PRD 的用户结果指标；本文件不是自动化测试，也不预先宣称通过。

## 1. 验证问题

本轮只回答四个产品问题：

1. 目标用户能否在不接受操作提示的情况下，从导入数据走到第一份描述统计结果？
2. 用户能否只通过“分析”方法库找到并配置常见方法？
3. 用户能否理解结果位于 Output，并区分当前、旧设置和失败运行？
4. 三工作区、局部守门和渐进披露是否降低了误操作与主观负担？

统计结果本身的数值正确性不在本研究中判定，相关证据由能力验证清单负责。

## 2. 参与者与环境

- 建议首轮 6–8 人，至少覆盖 3 名 SPSS/Jamovi 心智模型的硕博研究者、2 名研究助理或小团队成员、1 名方法敏感型用户。
- 参与者不得是本轮界面的实现者；研究主持人不得在任务中解释按钮位置或正确路径。
- 使用同一个拟发布 Windows 构建，并记录准确 Git commit、应用版本、屏幕尺寸、输入方式和是否使用辅助技术。
- 使用仓库随附的合成示例数据；不把参与者的真实研究数据或身份信息提交到仓库。
- 如需录屏、录音或保存自由文本反馈，应在开始前取得同意，并将材料保存在仓库之外的受控位置。

## 3. 固定任务

| 任务 | 给参与者的指令 | 主要指标 | PRD 目标 |
| --- | --- | --- | --- |
| T1 首次描述统计 | “请导入这份数据，并查看你认为合适的描述统计结果。” | 独立完成、用时、求助、错误路径 | 完成率 ≥85%；中位用时 ≤90 秒（宽限上限 120 秒） |
| T2 方法发现 | “请找到可以分析两个变量关系的相关分析方法，但先不要运行。” | 找到正确方法的用时、是否进入多个平级入口 | 中位用时 ≤10 秒；方法入口数量为 1 |
| T3 简单中介 | “请配置 X→M→Y 的简单中介，并运行一次。” | 变量角色成功率、主要交互次数、阻断理解 | 角色定位成功率 ≥90%；主要交互 ≤5 次，不含变量多选 |
| T4 结果与旧运行 | “修改一个设置后重新运行，再找到第一次运行的结果。” | 旧结果可回看、当前/旧设置辨识、静默覆盖 | 可回看率 100%；静默覆盖 0 |
| T5 警告与详情 | “请说明当前结果有哪些警告，以及使用了什么数据和方法。” | 严重警告发现、技术详情可达、解释是否越界 | 严重警告隐藏 0；来源信息可追溯 |
| T6 键盘路径 | “不使用鼠标，从三个工作区导航到分析方法搜索并返回数据。” | 是否完成、焦点丢失、键盘陷阱 | 核心路径完成率 100% |

如果参与者的背景不适合中介分析，可将 T3 替换为信度或分层回归；替换必须在开始前记录，不能根据结果临时挑选更容易的任务。

## 4. 主持规则

1. 开始前说明评估对象是软件而不是参与者，不介绍界面结构。
2. 每项任务从相同初始工作区开始；主持人只朗读任务，不示范操作。
3. 参与者明确求助时，先记录一次求助，再提供最小提示；提示后的完成不计为“独立完成”。
4. 系统错误、统计运行失败和主持人操作失误分别编码，不能全部归为用户错误。
5. 任务结束后才询问“你原本预期在哪里找到它”“哪个词或状态让你犹豫”。
6. 最后收集 1–7 分的易学性、定位清晰度、结果信任感和整体负担；可另行使用正式量表，但不得在仓库中复制受限问卷正文。

## 5. 事件与结果记录

每位参与者使用匿名编号。每个任务至少记录：

| 字段 | 允许值或说明 |
| --- | --- |
| participantId | `P01` 等匿名编号 |
| buildCommit | 40 位拟发布 commit |
| taskId | `T1`–`T6` |
| startedAt / endedAt | 本地时间及时区 |
| independentSuccess | `yes` / `no` |
| completionSeconds | 从读完任务到完成或放弃 |
| assistanceCount | 主持人提供提示的次数 |
| wrongTurns | 进入后又退出的错误入口数 |
| blockingDefect | 缺陷编号或 `none` |
| observedPath | 简短记录实际操作路径 |
| participantComment | 去标识化的简短摘要，不保存姓名或单位 |

原始逐人记录不提交到公开仓库。仓库只保存按任务聚合的分母、分子、中位数、范围、失败类型及去标识化结论。

## 6. 分析与发布判定

- 完成率以“未获得主持人提示且到达正确终态”的人数除以适用参与者人数。
- 时间只对独立完成者报告中位数和范围；同时单列超时或未完成数，不能将失败者从分母删除。
- 少量参与者研究不报告虚假的小数精度或推断检验；逐项列出可复现的严重阻断。
- 任一数据丢失、运行结果静默覆盖、严重警告不可见或键盘陷阱均视为发布阻断问题。
- 其他指标未达目标时，记录任务、界面位置和观察证据，再决定修复或接受风险；不得通过改写分母关闭问题。

发布记录至少包含：构建 commit、参与者构成、任务版本、汇总表、阻断问题清单、修复 commit 和复测结果。只有实际参与者数据齐备后，PRD 的真人可用性状态才能从“待执行”改为“已验证”或“未通过”。
