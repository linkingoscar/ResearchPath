# 工程开发与验证

## 开发环境

使用 PowerShell 7 和项目脚本：

```powershell
./scripts/setup.ps1
./scripts/dev.ps1
./scripts/harness.ps1 -Mode Quick
```

`setup.ps1` 建立 Python 虚拟环境、固定 R 运行时与依赖库、Node 依赖和 Playwright Chromium。依赖版本由 lock 文件控制。

## 三级验证

| 变更规模 | 命令 | 适用场景 |
| --- | --- | --- |
| 小 | `./scripts/harness.ps1 -Mode Quick` | 文案、样式、小型组件和局部实现 |
| 中 | `./scripts/harness.ps1 -Mode Targeted -BaseRef HEAD~1` | 中等单一功能：Quick 一次，再运行相关模块的明确测试清单 |
| 大 | `./scripts/harness.ps1 -Mode Full` | 跨领域重构、统计/契约根基、安全与任务生命周期、CI/依赖锁或发布候选 |

分级只有三种：小改动用 Quick；中等功能用 Quick + Targeted；跨域重构、统计/契约根基和发布候选直接用 Full。共享安全、任务生命周期和运行基础设施按 Full 处理。Targeted 命令已包含一次 Quick，不要再单独串联 Quick；升级 Full 时先解析影响范围，直接运行 Full，避免重复检查。

不得通过提高覆盖率、bundle、性能或统计容差来掩盖失败。修复应落在最接近风险的代码层和测试层，不为同一事实建立重复脚本或文档哈希。

## Quick

Quick 覆盖架构路径、Python lint/type、Web lint/type 和契约生成漂移。它用于快速反馈，不证明完整统计链或浏览器旅程通过。

## Targeted

`scripts/test-impact-map.json` 是唯一影响映射：文档和局部样式进入 Quick；共享基础设施、统计公共函数和跨语言契约进入 Full；单一领域功能进入 Targeted。模块规则按顺序匹配，专用领域置于通用目录之前。未知路径、跨领域改动、缺失测试映射或无法确定变更范围时保守升级 Full。代码改动的大小不能仅靠行数推断；明确的小型机械改动可由开发者选择 Quick。

Targeted 计划携带 API、Web、R 和 E2E 的具体测试文件。API 改动只选择该模块的 API 测试；Web 改动选择该模块的组件测试和登记的浏览器旅程；R 方法改动选择对应 R 测试和 API 数值集成；只修改测试文件时运行该文件。测试清单也用于确定模块归属，同一模块的源码与测试一起修改不会因此升级 Full；通用目录的测试通配符会排除已归属专用模块的测试。API 模块测试串行执行以兼容 `serial` 标记；R 保留需要隔离运行的 GLMM 测试。空清单、越界或不存在的测试路径会被拒绝，绝不解释为“运行全部”。Targeted 不生成全量覆盖率。

日常 PR 和 main 推送按解析出的 Quick / Targeted / Full 执行。checkout 拉取完整历史；PR 使用事件中的 base SHA 与待测合并提交比较，推送使用 before SHA 与当前提交比较，覆盖全部提交。CI 使用 `-DiffMode direct`，包含历史改写时的删除；本地默认仍为 merge-base 比较。重命名保留原路径删除和新路径新增两侧的测试范围。

CI 根据计划准备依赖：Quick 和仅 Web 单测使用 Python/Node；需要 API、R、浏览器或 Full 时复用 `setup.ps1` 和 R/Rtools 缓存。相关浏览器测试前构建生产前端，不再一律运行全部 smoke。手动触发保留 Full 和依赖审计。影响解析器、CI 分支和测试选择器的回归测试归入 Full，不另设第四级门禁。

浏览器检查失败时，CI 在 `playwright-failure-<run-id>-<attempt>` 附件中保留失败截图及 `error-context.md` 页面状态 7 天。附件仅收集 CI 生成的这两类文件，不上传整个运行目录或包含会话请求信息的 trace；原始 trace 仅供本地排查。先确认失败步骤和断言，再依据证据修复，不以重试通过代替根因验证。

可先审阅计划，再运行中等功能验证：

```powershell
./.venv/Scripts/python.exe scripts/resolve-test-impact.py --root . --base-ref HEAD~1
./scripts/harness.ps1 -Mode Targeted -BaseRef HEAD~1
```

`-ChangedFile` 可显式提供本次改动路径，但不得用它隐去同一变更中的其他受影响模块。发布候选始终显式使用 `-Mode Full`。

## Full

Full 由 `scripts/test.ps1` 编排，覆盖：

- 架构、依赖锁、lint、类型和契约；
- Python API 与服务测试及覆盖率；
- R `testthat`、独立数值基准和跨语言集成；
- Web 单测、生产构建和 bundle 预算；
- Playwright 关键用户路径、严重无障碍问题和响应式溢出。

Full 是大改动和发布候选的单一完整入口。依赖审计或性能基准在相关依赖、安全或性能工作中单独执行，不叠加成另一个常规门禁层级。

## 统计测试分层

1. 纯函数或公式：固定输入、边界和数值容差。
2. R estimator：估计器、包版本、回退、收敛和异常解。
3. Python service：任务、文件绑定、错误翻译和结果 schema。
4. API：请求、响应、生命周期和导出。
5. Web：配置可达、状态语义和真实结果呈现。
6. E2E：从数据到结果的关键用户路径。

统计改动先运行受影响的较低层测试；只有跨切片、共享执行器、核心契约或发布候选才需要 Full。

## 代码修改约束

- 先找领域入口，再修改聚焦模块。
- 协议变化同步 schema、Python、TypeScript 和测试。
- 统计方法变化同步执行记录、结果警告和导出。
- 不在仓库根目录写生成测试数据；运行状态使用忽略目录。
- 不提交临时计划、运行日志、浏览器截图或一次性审查材料。
