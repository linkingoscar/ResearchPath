# 工程开发与验证

## 开发环境

使用 PowerShell 7 和项目脚本：

```powershell
./scripts/setup.ps1
./scripts/dev.ps1
./scripts/harness.ps1 -Mode Quick
```

`setup.ps1` 建立 Python 虚拟环境、固定 R 运行时与 `renv` 库、Node 依赖和 Playwright Chromium。依赖版本由 lock 文件控制。bootstrap `renv` 位于 `.runtime/renv-bootstrap-library`，与 `.runtime/R-library` 中按 `renv.lock` 恢复的应用包隔离；固定版本的 `qs2`/`jsonlite` 只有在缺失、不可加载或版本失配时才重建。

## 必须执行的 Harness

| 场景 | 命令 | 内容 |
| --- | --- | --- |
| 聚焦改动后 | `./scripts/harness.ps1 -Mode Quick` | 架构、Python lint/type、Web lint、契约漂移 |
| 单个工作包验证 | `./scripts/harness.ps1 -Mode Targeted -BaseRef HEAD~1` | Quick + 改动影响映射命中的无覆盖率专项；未知/共享基础设施改动自动升级 Full |
| 统计/契约工作包 | `./scripts/harness.ps1 -Mode Statistical` | Quick + API 无覆盖率全量、R lock/testthat/独立金标准、契约和 Web 单测 |
| 合并前 | `./scripts/harness.ps1 -Mode Full` | `scripts/test.ps1` 全质量门禁 |
| 发布候选 | `./scripts/harness.ps1 -Mode Release` | Full、依赖审计、R 性能基准、发布证据 |

`Targeted` 默认同时读取 `BaseRef...HEAD`、工作区、暂存区和未跟踪文件；也可用重复的 `-ChangedFile <path>` 对影响映射本身做确定性验证。映射定义在 `scripts/test-impact-map.json`：未知文件、脚本/CI/锁文件等共享基础设施必须 fail-safe 升级为 Full。Targeted 的输出会明确列出 changed files、risk、lanes、deferred 与 escalation；它不生成覆盖率，因此不能替代合并前 Full。`Statistical` 用于统计引擎、跨语言契约和结果解释改动的开发闭环，也不能替代 Full。

不得提高覆盖率、类型、bundle、性能或统计容差来掩盖失败。跳过 Release 步骤会得到 `incomplete`，不能写成发布通过。

## Full 门禁范围

`scripts/test.ps1` 是唯一编排入口，覆盖：

- 架构规则和依赖锁；
- Ruff、Python 类型与 Pytest；
- R `testthat` 单元测试及 Python→R 集成测试；
- Web lint、Vitest、TypeScript、生产构建与 bundle budget；
- Playwright E2E：规划/入口、嵌套横截面、面板、日记、模型画布，原始变量按需分析、SEM 真实估计，以及三条上传→测量→实证→结果→Excel 内容核验的完整研究链路；同时检查未预期页面/HTTP/控制台错误、严重可访问性违规与移动端横向溢出；
- 契约生成一致性。

Full 的 Python/Web/契约/依赖锁/R 单测前置检查按四个只读任务并行，任一任务失败仍会使门禁失败。API 测试的常规通道使用 `xdist --dist=worksteal`；2026-07-29 在相同覆盖率和真实 R 负载下，4/6/8 worker 分别为 181.89/185.05/183.57 秒，因此默认保留 4 worker。每个 worker 及其 R 子进程的 OpenMP、BLAS、NumExpr 与 RcppParallel 原生线程预算固定为 1，测试结束后恢复调用者环境。对 hosted runner 上对资源竞争敏感且带墙钟上限的 `serial` 真实 R 估计器用例，以及会创建并测量自身驻留 worker pool 的资源/并发测试，Full 先在常规通道排除，再以单进程串行通道运行，最后合并覆盖率；不改变测试数据、统计模拟次数、子进程超时、性能预算或质量容差。

GitHub 的 push/PR Full 不下载第三方 Hayes 数据包；相关公开数据 oracle 在资源缺失时显式 skip。需要重跑该外部对照时，使用 `workflow_dispatch`：工作流先下载固定 URL、核对固定 SHA-256，再运行同一 Full。这样第三方 TLS 或可用性故障不会在项目测试开始前阻断每个提交，手动外部验证仍保持失败可见，不能以默认 CI 绿色替代。

R 层已经有独立 `testthat` 入口：`engine/R/tests/testthat.R`，由 `scripts/test-r.ps1` 调用并纳入 Full。Full 的 R 前置任务还会运行 `scripts/check-r-numeric-baselines.py`：它将独立参考模型重算至临时目录，逐字段校验数据 SHA、包版本、JSON 形状与金标准容差，且不改写受版本控制的夹具。该检查以脚本、R 源码、参考输入、受控金标准、`renv.lock` 和固定 R 运行时版本组成内容身份；Full 仅在完全相同身份已有成功证据时复用忽略目录中的缓存，Release 始终 `--no-cache` 独立重算。缓存不保存估计结果、不能容忍漂移，任何相关内容变化都会失效。此外 `engine/R/tests/reference/process-goldens.json` 保存官方 PROCESS 5.0 R 宏生成的五模型数值金标准（`generate-process-goldens.R` 为独立参考生成器，不调用产品 runner），`test-process-goldens.R` 逐项对照真实 runner 输出。Python 集成测试继续验证跨语言契约。R 包升级时，应在 R 单测中验证细粒度数值与警告，在 Python 集成中验证序列化与业务路径。

Full/Release 成功后会把质量前置、API 覆盖率、Web/E2E/build 和总耗时写入忽略目录 `output/test-performance/harness-timing.json`，并向 `harness-timing.ndjson` 追加带 commit、dirty 状态、worker 数与缓存状态的机器可读记录。只有在这些数据证明资源预算稳定后，才考虑 API/Web 更深并行、R suite 分片或提高 Playwright workers；不能仅凭单次体感启用并行。

`setup.ps1` 在 R lock 版本校验后还会通过 `scripts/check-glmmtmb-abi.R` 检查 `glmmTMB` 记录的 TMB build version。CRAN Windows binary 若在包版本不变时被上游原地重建，版本锁仍会通过，但 ABI 探测会失败；setup 随后验证固定源码归档的 SHA-256，并在已锁定 TMB 与 Rtools 上单任务重建 `glmmTMB`，再次校验 lock 和 ABI。

## 统计测试分层

1. 纯函数/公式：固定输入、边界和数值容差。
2. R estimator：估计器、包版本、回退、收敛和异常解。
3. Python service：任务、文件绑定、错误翻译和结果 schema。
4. API：请求/响应、生命周期、导出。
5. Web：配置可达、状态语义、真实 segment 呈现。
6. E2E：从数据到结果的关键用户路径。

升级 `lavaan`、`psych`、`lme4`、`testthat` 等 R 包时，必须运行 R 单测、相关专项、Quick 和 Full，并检查预期数值漂移；不能仅依赖“JSON 能返回”。

## 代码修改约束

- 先找领域入口，再修改聚焦模块。
- 协议变化同步 schema、Python、TypeScript 和测试。
- 统计方法变化同步执行记录、结果警告和导出。
- 不在仓库根目录写生成测试数据；运行状态使用忽略目录。
- 不把 archive 中的历史脚本加入活动 import、route 或构建。
