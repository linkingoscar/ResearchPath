# 运行维护与发布

## Windows R 源码构建路径

Rtools 链接器无法可靠解析含非 ASCII 字符的库搜索路径；库文件存在时仍可能报 `cannot find -lR`、`-lRcppParallel` 或 `-ltbb`。`qs2` / `glmmTMB` 需要源码构建时，安装脚本先检查 R 和用户库的真实路径并给出明确错误，避免完成编译后才在链接阶段失败。

当前处理方式是在纯英文实体目录中准备运行环境，保持 `renv.lock` 和源码包版本不变。R 的 `normalizePath()` 会将 junction 和 `subst` 映射还原为原目录，因此这两种别名不能解决用户库路径问题。不要删除依赖锁或升级包来规避它。

```powershell
$env:R_LIBS_USER = Join-Path $PWD '.runtime/R-library'
$env:LC_ALL = 'English_United States.utf8'
./.runtime/R/bin/Rscript.exe --vanilla scripts/check-r-build-path.R
```

若安装在 `qs2` 阶段停止，后续 `jsonlite` 及完整依赖恢复尚未执行；Full 中的 `jsonlite is required to validate renv.lock` 是安装中断的后续症状，不能据此将根因判为单独缺少 jsonlite。

## 桌面轻应用

首次安装：

```powershell
./scripts/setup.ps1
./scripts/install-app.ps1
```

`install-app.ps1` 执行生产 Web 构建，并创建桌面快捷方式。快捷方式通过隐藏的 PowerShell 7 启动单个 FastAPI 生产进程，再以专用 Edge profile 打开 `--app` 窗口。日常运行只有 `127.0.0.1:9999`：API 路由先注册，生产静态文件最后挂载在 `/`，不存在 Vite 开发服务器。

生命周期规则：

- 命名互斥锁防止重复启动；
- 只清理能够确认属于本项目的旧 API 进程；
- Edge profile 位于 `.researchpath/edge-profile/`，与用户日常浏览器隔离；
- 关闭 Edge 应用窗口后，隐藏启动器回收 API；
- 启动异常通过 Windows 对话框显示，详细日志写入 `.researchpath/logs/`。

根目录 `启动研径.cmd` 是备用入口。前端代码或图标更新后，应重新运行 `scripts/install-app.ps1`，不能继续使用过期的 `apps/web/dist`。

## 开发启动

开发者使用：

```powershell
./scripts/dev.ps1
```

开发模式固定使用 `127.0.0.1:9999`（API）和 `127.0.0.1:5173`（Vite Web），保留终端并支持前端开发服务。启动窗口关闭或按 `Ctrl+C` 后，清理对应进程。

运行数据和 Edge profile 都位于受控本地目录，不应提交到 Git。

## 故障定位

1. 桌面模式检查 `.researchpath/logs/desktop-launcher.log` 与 `desktop-api.err.log`；开发模式检查 `api.err.log` 与 `web.err.log`。
2. 确认端口未被无关进程占用。
3. 执行 Quick，排除架构、类型和契约漂移。
4. 对 R 错误记录 R/package 版本、实际方法、输入规格和回退信息。
5. 不用删除整个工作区作为首选修复。

## 环境变量

`apps/api/app/settings.py` 读取以下变量；整数解析失败或越界会记 `logger.warning` 并按默认值/钳制继续，不会静默失败：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `RESEARCHPATH_R_WORKERS` | 1（1–2） | 常驻 R worker 池大小 |
| `RESEARCHPATH_R_PARALLEL_WORKERS` | 按 CPU 推导（1–核数/worker） | 每个 worker 的并行 R 子进程数 |
| `RESEARCHPATH_ANALYSIS_QUEUE_CAPACITY` | 8（0–100） | 等待队列容量 |
| `RESEARCHPATH_RUNTIME_TMP_MAX_AGE_HOURS` | 24 | 上传残留清理期限 |
| `RESEARCHPATH_RUNTIME_RUNS_MAX_AGE_DAYS` | 30 | runs 结果目录清理期限 |
| `RESEARCHPATH_SERVE_WEB` | false | 生产模式挂载前端静态资源 |
| `RESEARCHPATH_BOOTSTRAP_TOKEN` | 随机 | 一次性启动凭据（单次消费） |
| `RESEARCHPATH_SESSION_TOKEN` | 随机 | 会话令牌固定覆盖；未设置时每次启动随机，重启后旧令牌失效属预期 |

## 取消分析与 R worker 生命周期

取消会等待正在执行的任务退出并清理工作目录后记录终态，不能以 DELETE 已接受或 result 为空代替清理证据。Windows 常驻 worker 以挂起方式创建，加入当前服务实例拥有的 Job Object 后才恢复运行，确保 Rscript/Rterm 与其子进程归属于同一树；取消只终止该树，不按进程名称扫描杀进程。机制参考 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

worker 补建在共享池锁之外执行并接收取消信号；被取消的任务默认不等待新 worker 启动，后续任务按容量预留补建。重复负载回归包含真实 bootstrap、终态、工作目录清理、后续运行与进程树隔离，保留 2.5 秒取消预算。

## 发布候选

```powershell
./scripts/harness.ps1 -Mode Full
```

发布必须同时满足：

- Full 验证通过；
- 依赖审计完成；
- R runtime benchmark 完成；
- 当前文档与 `project.manifest.json` 对齐；
- 根 `LICENSE`、README、NOTICE 与包元数据的分发边界一致；
- 没有把 experimental 切片误写成无边界正式能力；
- 备份恢复演练对本次数据格式仍有效。

发布者必须确认 Full 运行对应拟发布提交；其他提交的成功记录不能替代当前候选。发布流程不假设 required checks 或分支保护已经配置。

## 公开介绍页

介绍页源码位于 `pages/`，生产地址为 [researchpath-pied.vercel.app](https://researchpath-pied.vercel.app/)。发布内容只介绍产品边界并链接公开仓库，不上传本地研究数据。GitHub Pages workflow 保留为手动发布备用路径；仓库首次启用 Pages 仍需所有者在 Settings → Pages 中选择 GitHub Actions，未启用前不在每次 `main` 提交上重复产生已知权限失败。

## 可复现导出

导出至少携带：

- 数据/测量/规格/结果身份；
- 实际方法与引擎版本；
- 随机种子和关键参数；
- 样本流、警告、回退与诊断；
- 表格和图形对应的结果字段。

导出路径必须绑定到当前任务和结果对象。不得接受仅凭可控路径字符串读取任意本地文件。

## 性能与容量

性能与覆盖率基线只保留在仍被自动化验证消费的位置。新增大样本、模拟或导出功能应先定义内存、时间、行数、备份大小和并发预算，再实现副作用。
