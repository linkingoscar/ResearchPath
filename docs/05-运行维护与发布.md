# 运行维护与发布

## 桌面轻应用

首次安装：

```powershell
./scripts/setup.ps1
./scripts/install-app.ps1
```

`install-app.ps1` 执行生产 Web 构建，并创建桌面快捷方式。快捷方式通过隐藏的 PowerShell 7 启动单个 FastAPI 生产进程，再以专用 Edge profile 打开 `--app` 窗口。日常运行只有 `127.0.0.1:9999`：API 路由先注册，生产静态文件最后挂载在 `/`，不存在 Vite 开发服务器。

生命周期规则：

- 命名互斥锁防止重复启动；
- 只清理能够确认属于本项目的旧 API 进程；
- Edge profile 位于 `.researchpath/edge-profile/`，与用户日常浏览器隔离；
- 关闭 Edge 应用窗口后，隐藏启动器回收 API；
- 启动异常通过 Windows 对话框显示，详细日志写入 `.researchpath/logs/`。

根目录 `启动研径.cmd` 是备用入口。前端代码或图标更新后，应重新运行 `scripts/install-app.ps1`，不能继续使用过期的 `apps/web/dist`。

## 开发启动

开发者使用：

```powershell
./scripts/dev.ps1
```

开发模式固定使用 `127.0.0.1:9999`（API）和 `127.0.0.1:5173`（Vite Web），保留终端并支持前端开发服务。启动窗口关闭或按 `Ctrl+C` 后，清理本轮进程。

运行数据和 Edge profile 都位于受控本地目录，不应提交到 Git。

## 故障定位

1. 桌面模式检查 `.researchpath/logs/desktop-launcher.log` 与 `desktop-api.err.log`；开发模式检查 `api.err.log` 与 `web.err.log`。
2. 确认端口未被无关进程占用。
3. 执行 Quick，排除架构、类型和契约漂移。
4. 对 R 错误记录 R/package 版本、实际方法、输入规格和回退信息。
5. 不用删除整个工作区作为首选修复。

## 环境变量

`apps/api/app/settings.py` 读取以下变量；整数解析失败或越界会记 `logger.warning` 并按默认值/钳制继续，不会静默失败：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `RESEARCHPATH_R_WORKERS` | 1（1–2） | 常驻 R worker 池大小 |
| `RESEARCHPATH_R_PARALLEL_WORKERS` | 按 CPU 推导（1–核数/worker） | 每个 worker 的并行 R 子进程数 |
| `RESEARCHPATH_ANALYSIS_QUEUE_CAPACITY` | 8（0–100） | 等待队列容量 |
| `RESEARCHPATH_RUNTIME_TMP_MAX_AGE_HOURS` | 24 | 上传残留清理期限 |
| `RESEARCHPATH_RUNTIME_RUNS_MAX_AGE_DAYS` | 30 | runs 结果目录清理期限 |
| `RESEARCHPATH_SERVE_WEB` | false | 生产模式挂载前端静态资源 |
| `RESEARCHPATH_BOOTSTRAP_TOKEN` | 随机 | 一次性启动凭据（单次消费） |
| `RESEARCHPATH_SESSION_TOKEN` | 随机 | 会话令牌固定覆盖；未设置时每次启动随机，重启后旧令牌失效属预期 |

## 取消分析与 R worker 生命周期

取消会等待正在执行的任务退出并清理工作目录后记录终态，不能以 DELETE 已接受或 result 为空代替清理证据。Windows 常驻 worker 以挂起方式创建，加入本轮拥有的 Job Object 后才恢复运行，确保 Rscript/Rterm 与其子进程归属于同一树；取消只终止该树，不按进程名称扫描杀进程。机制参考 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

worker 补建在共享池锁之外执行并接收取消信号；被取消的任务默认不等待新 worker 启动，后续任务按容量预留补建。重复负载回归包含真实 bootstrap、终态、工作目录清理、后续运行与进程树隔离，保留 2.5 秒取消预算。

## 发布候选

```powershell
./scripts/harness.ps1 -Mode Release
```

发布必须同时满足：

- Full 质量门禁通过；
- 依赖审计完成；
- R runtime benchmark 完成；
- 发布证据写入成功；
- 当前文档与 `project.manifest.json` 对齐；
- 根 `LICENSE`、README、NOTICE 与包元数据的分发边界一致；
- 没有把 experimental 切片误写成无边界正式能力；
- 备份恢复演练对本次数据格式仍有效。

本地 Release 或 GitHub Actions 机器证据的 `source.commit` 必须与拟发布 SHA 完全一致，且 `evidenceComplete=true`；测试过其他提交的绿色记录不能替代当前候选。仓库现已公开且默认分支为 `main`，但发布流程不假设 required checks 或分支保护已经配置；在取得当前设置的明确证据前，任何发布仍须人工核对上述 SHA 绑定，不能把“默认分支最新”当成已测试证明。DEBT-062/144 保留为历史上已接受的外部治理风险，不用于描述当前代码是否通过。

## 可复现导出

导出至少携带：

- 数据/测量/规格/结果身份；
- 实际方法与引擎版本；
- 随机种子和关键参数；
- 样本流、警告、回退与诊断；
- 表格和图形对应的结果字段。

导出路径必须绑定到当前任务和结果对象。不得接受仅凭可控路径字符串读取任意本地文件。

## 性能与容量

活动性能与覆盖率基线只保留在仍被门禁消费的位置。历史性能快照已移到 `archive/project-history/performance-baselines/`，不能作为当前预算。新增大样本、模拟或导出功能应先定义内存、时间、行数、归档大小和并发预算，再实现副作用。
