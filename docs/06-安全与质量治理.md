# 安全与质量治理

## 安全边界

本地优先不等于无安全风险。系统必须保证：

- API 仅监听 loopback；
- 一次性凭据和来源校验不被绕过；
- 数据读写请求携带会话令牌；公开白名单仅限 health、demo、能力目录与经过字段投影的 SSE 进度流；
- 空或过短的 `RESEARCHPATH_SESSION_TOKEN` / `RESEARCHPATH_BOOTSTRAP_TOKEN` 导致启动失败，不静默关闭鉴权；
- 用户可控路径经过规范化、containment、对象身份和资源预算校验；
- 备份解压限制条目数、单文件大小、总大小和路径穿越；
- R 通过参数与受控文件通信，不拼接用户命令；
- 原始数据、日志和结果不进入版本库；
- 错误响应不暴露任意本机路径或敏感内容；
- 静态托管设置 CSP、`nosniff` 和 `X-Frame-Options`；CSV/XLSX 导出统一处理公式注入。

## 持续风险与控制

| 风险 | 控制 |
| --- | --- |
| 统计方法名与实际执行不一致 | `methodExecution`、显式回退、稳定警告码和导出字段 |
| 高级能力被过度宣传 | registry + slice + `executionAvailable`，并分别披露验证层级、成熟度和论文资格 |
| 路径越界或对象错绑 | containment、identity、resource budget 和原子发布 |
| R 包升级造成数值漂移 | `testthat`、Python 集成、独立数值基准和 Full 验证 |
| 共享统计逻辑复制分叉 | 共用数据准备与估计 helper，修改后运行相关统计专项 |
| SSE 监听器耗尽 | 每个运行与全局连接上限，超限时前端回退轮询 |
| 文档与实现漂移 | 能力目录测试、manifest 路径检查和契约生成检查 |

## 变更要求

- 安全、性能、全仓清理和发布准备前先读工程与验证文档。
- 先确认目标、对象身份和影响边界，再执行写入、移动、恢复或清理。
- 确认的问题应进入可复现测试或当前边界文档，不维护公开的内部工单流水账。
- 测试数量和单次运行耗时不作为永久质量声明。
- `project.manifest.json`、文档和活动路由不一致时，以实现为依据同步修正并增加必要验证。

## 高风险修复

1. 固定触发条件、输入和对象身份。
2. 建立最小回归测试。
3. 修复 service 或 engine 的根因。
4. 验证 HTTP 映射、持久化、导出和恢复路径。
5. 运行与影响匹配的专项及 Full 验证。
6. 更新当前安全、统计或产品边界文档。
7. 将临时日志、截图和复盘材料保存在版本库之外。
